Analysis of Recursive Algorithms

How to set up a recurrence relation for a recursive algorithm, solve it, and avoid the exponential trap.

Goals and learning outcomes

The goal of this module is to learn to analyze algorithms that call themselves. Instead of sums, we now deal with recurrence relations. The module builds on the analysis plan and the summation formulas from Module 1.

After this module you will be able to:

  1. apply the general plan of analysis to a recursive algorithm;
  2. set up a recurrence relation and find the initial condition from the line where the recursion stops;
  3. solve recurrences by the method of backward substitutions and verify the answer by mathematical induction;
  4. build the tree of recursive calls and count calls with it;
  5. solve recurrences with $\lfloor n/2\rfloor$ for $n = 2^k$ and extend the answer to all $n$ by the smoothness rule;
  6. recognize repeated subproblems and eliminate them by memoization or iteration;
  7. estimate the memory of a recursion through the depth of the call stack and explain what tail recursion gives.

General plan for recursive algorithms

This plan differs from the Module 1 plan in its fourth and fifth steps (Levitin, §2.4):

  1. Decide on a parameter indicating an input's size.
  2. Identify the algorithm's basic operation.
  3. Check whether the number of times the basic operation is executed can vary on different inputs of the same size. If it can, the worst-case, average-case, and best-case efficiencies must be investigated separately.
  4. Set up a recurrence relation, with an appropriate initial condition, for the number of times the basic operation is executed.
  5. Solve the recurrence or, at least, ascertain the order of growth of its solution.

A recurrence relation expresses $M(n)$ through its values at smaller arguments. For example, $M(n) = M(n-1) + 1$: “the work for $n$ = the work for $n-1$ plus one operation”. Infinitely many sequences satisfy it: $n$, $n + 5$, $n - 3$… The initial condition, the value at the smallest argument, singles out one of them. It is taken from the line where the recursion stops: that line shows both the smallest $n$ and the number of basic operations performed for it.

Method of backward substitutions

The main method of this module is the method of backward substitutions. The steps are:

  1. Write down the recurrence for $x(n)$.
  2. Replace $n$ by $n-1$ in it to express $x(n-1)$ through $x(n-2)$, and substitute into the original equation.
  3. Repeat for $x(n-2)$, then for $x(n-3)$. Three lines are usually enough to see the pattern.
  4. Write the general formula after $i$ substitutions: $x(n)$ in terms of $x(n-i)$ and $i$.
  5. Choose $i$ so that $n - i$ equals the argument of the initial condition, and substitute its value.
  6. Simplify (a summation formula is often needed) and verify the result: by substituting into the equation and the initial condition, or by induction.

Strictly speaking, the pattern from step 4 itself requires a proof by induction on $i$. Levitin notes that it is easier to obtain the answer first and then prove its correctness. That is what we will do.

Example: $x(n) = x(n-1) + n$, $x(0) = 0$ (Appendix B).

$$\begin{aligned} x(n) &= x(n-1) + n = [x(n-2) + (n-1)] + n = [x(n-3) + (n-2)] + (n-1) + n \\ &= x(n-i) + (n-i+1) + \dots + (n-1) + n \\ &\overset{i=n}{=} x(0) + 1 + 2 + \dots + n = \frac{n(n+1)}{2}. \end{aligned}$$

Verifying the result by induction

An answer found from a pattern is still only a hypothesis. Mathematical induction turns it into a theorem. Let us prove that the solution of the Tower of Hanoi recurrence $M(n) = 2M(n-1) + 1$, $M(1) = 1$ (derived below) is $M(n) = 2^n - 1$ for all $n \ge 1$.

Statement $P(n)$: $M(n) = 2^n - 1$.

Basis, $n = 1$: by the initial condition $M(1) = 1$, and by the formula $2^1 - 1 = 1$. They agree.

Inductive step. Let $n \ge 2$ and suppose $P(n-1)$ holds: $M(n-1) = 2^{n-1} - 1$. Then by the recurrence $$M(n) = 2M(n-1) + 1 = 2\left(2^{n-1} - 1\right) + 1 = 2^n - 2 + 1 = 2^n - 1,$$ so $P(n)$ holds.

Conclusion. By the principle of mathematical induction, $M(n) = 2^n - 1$ for all $n \ge 1$.

The inductive step is simply substituting the formula into the right-hand side of the recurrence; the basis is checking the initial condition. For recurrences with $\lfloor n/2\rfloor$, strong induction is used: the statement is assumed for all smaller values (problems C1 and C2).

Worked example 1. Factorial

$n! = 1\cdot2\cdot\ldots\cdot n = (n-1)!\cdot n$ for $n \ge 1$ and $0! = 1$. This gives a recursive algorithm:

ALGORITHM F(n)
//Computes n! recursively
//Input: A nonnegative integer n
//Output: The value of n!
if n = 0 return 1
else return F(n − 1) ∗ n
1. Input size
For simplicity, the number $n$ itself rather than the number of bits in its binary representation.
2. Basic operation
Multiplication. Denote the number of multiplications by $M(n)$.
3. Cases
None: everything is determined by $n$.
4. Recurrence
To compute $F(n)$, we need $M(n-1)$ multiplications to compute $F(n-1)$ and one more to multiply the result by $n$: $$M(n) = M(n-1) + 1 \ \text{ for } n > 0.$$ The initial condition comes from the line if $n = 0$ return 1: the recursion stops at $n = 0$ and performs no multiplications, so $M(0) = 0$.
5. Solution
$M(n) = M(n-1) + 1 = M(n-2) + 2 = M(n-3) + 3 = \dots = M(n-i) + i$. The initial condition is given at $0$, so take $i = n$: $M(n) = M(0) + n = n$.
Class
$M(n) = n \in \Theta(n)$.

Two different recurrences. Do not confuse the recurrence for the values $F(n) = F(n-1)\cdot n$, $F(0) = 1$ (what is computed) with the recurrence for the number of multiplications $M(n) = M(n-1) + 1$, $M(0) = 0$ (how much work is done). The values grow as $n!$, while the work is linear. This confusion is the subject of problem F2.

A simple loop that accumulates the product performs the same $n$ multiplications, but without the time and space overhead of the recursion stack. The visualization shows this: the stack grows to $n + 1$ frames, and the multiplications are performed only on the way back.

Worked example 2. Tower of Hanoi

There are $n$ disks of different sizes and three pegs. Initially, all the disks are on the first peg, the largest at the bottom. The goal is to move all of them to the third peg, using the second one as an auxiliary. Only one disk can be moved at a time, and a larger disk may never be placed on top of a smaller one.

Recursive solution: to move $n > 1$ disks from A to C, (1) move $n-1$ disks from A to B, using C as auxiliary; (2) move the largest disk directly from A to C; (3) move $n-1$ disks from B to C, using A as auxiliary. If $n = 1$, the single disk is simply moved.

ALGORITHM Hanoi(n, from, to, aux)
//Moves n disks from peg from to peg to, using aux as auxiliary
if n = 1
    move disk from from to to
else
    Hanoi(n − 1, from, aux, to)
    move disk from from to to
    Hanoi(n − 1, aux, to, from)
1. Input size
The number of disks $n$.
2. Basic operation
Moving one disk. The number of moves is $M(n)$.
3. Cases
None: $M(n)$ depends only on $n$.
4. Recurrence
Two transfers of a tower of $n-1$ disks plus one move: $$M(n) = M(n-1) + 1 + M(n-1) = 2M(n-1) + 1 \ \text{ for } n > 1, \qquad M(1) = 1.$$ The initial condition is obvious: one disk, one move.
5. Solution
By backward substitutions below: $M(n) = 2^n - 1$.
Class
$M(n) = 2^n - 1 \in \Theta(2^n)$, an exponential algorithm.

Step-by-step derivation

Click the last line or the button to reveal the next step.

  1. $M(n) = 2M(n-1) + 1$ — substitute $M(n-1) = 2M(n-2) + 1$
  2. $\phantom{M(n)} = 2[2M(n-2) + 1] + 1 = 2^2M(n-2) + 2 + 1$ — substitute $M(n-2) = 2M(n-3) + 1$
  3. $\phantom{M(n)} = 2^2[2M(n-3) + 1] + 2 + 1 = 2^3M(n-3) + 2^2 + 2 + 1$ — the pattern is visible
  4. $\phantom{M(n)} = 2^iM(n-i) + 2^{i-1} + \dots + 2 + 1 = 2^iM(n-i) + 2^i - 1$ — after $i$ substitutions; the sum is a geometric series $\sum_{j=0}^{i-1}2^j = 2^i - 1$
  5. The initial condition is given at $n = 1$, so we need $n - i = 1$: $i = n - 1$ — not $i = n$: the value $M(0)$ is not given
  6. $M(n) = 2^{n-1}M(1) + 2^{n-1} - 1 = 2^{n-1} + 2^{n-1} - 1 = 2^n - 1$ — the answer
  7. Check: $M(1) = 2 - 1 = 1$; $2(2^{n-1} - 1) + 1 = 2^n - 1$. A rigorous proof by induction is given above.

Tree of recursive calls

When an algorithm calls itself more than once, it is useful to build a tree of recursive calls: its nodes are calls labeled with the parameter value, and the children of a node are the calls made from it. For Hanoi the root is $n$, and every node $m > 1$ has two children $m - 1$. Level $l$ contains $2^l$ nodes, and the levels are numbered from $0$ to $n-1$. The total number of calls is

$$C(n) = \sum_{l=0}^{n-1} 2^l = 2^n - 1.$$

The number of calls equals the number of moves, and this is no coincidence: each call makes exactly one move with “its own” disk. In the visualization below, the $k$th move is made by the $k$th node of the tree read from left to right.

The algorithm is exponential, yet it is not a bad one: it can be proved that the puzzle cannot be solved in fewer moves. The difficulty lies in the problem itself. Levitin's general lesson:

One should be careful with recursive algorithms because their succinctness may mask their inefficiency.

Worked example 3. Number of binary digits: BinRec

A recursive version of the algorithm Binary from Module 1:

ALGORITHM BinRec(n)
//Input: A positive decimal integer n
//Output: The number of binary digits in n's binary representation
if n = 1 return 1
else return BinRec(⌊n/2⌋) + 1
1. Input size
The number $n$.
2. Basic operation
The addition “$+1$”. The number of additions is $A(n)$.
3. Cases
None.
4. Recurrence
$A(\lfloor n/2\rfloor)$ additions for the nested call plus one more: $$A(n) = A(\lfloor n/2\rfloor) + 1 \ \text{ for } n > 1, \qquad A(1) = 0.$$ At $n = 1$ the recursion stops without any additions.
5. Solution
Because of $\lfloor n/2\rfloor$, backward substitutions “stumble” on values of $n$ that are not powers of 2. The standard approach is to solve it for $n = 2^k$: $$A(2^k) = A(2^{k-1}) + 1 = A(2^{k-2}) + 2 = \dots = A(2^{k-i}) + i = \dots = A(2^0) + k = k.$$ Returning to $n = 2^k$, $k = \log_2 n$: $A(n) = \log_2 n$.
Class
$A(n) \in \Theta(\log n)$ for all $n$, by the smoothness rule.

Why the answer for powers of 2 holds for all $n$. The smoothness rule (Levitin, Appendix B): let $T(n)$ be eventually nondecreasing and $f(n)$ a smooth function, that is, eventually nondecreasing with $f(2n) \in \Theta(f(n))$. If $T(n) \in \Theta(f(n))$ for values of $n$ that are powers of $b \ge 2$, then $T(n) \in \Theta(f(n))$ for all $n$. The functions $\log n$, $n$, $n\log n$, $n^\alpha$ ($\alpha \ge 0$) are smooth; $2^n$ is not, since $2^{2n} = 4^n \notin \Theta(2^n)$.

For BinRec, $A(n)$ is nondecreasing and $\log n$ is smooth, so $A(n) \in \Theta(\log n)$ for all $n$. The exact formula can also be stated: $A(n) = \lfloor\log_2 n\rfloor$. This is one less than the number of comparisons in the nonrecursive Binary ($\lfloor\log_2 n\rfloor + 1$): there we counted the comparisons $n > 1$, here we count additions.

Warning example: Fibonacci numbers

The Fibonacci numbers $0, 1, 1, 2, 3, 5, 8, 13, \dots$ are defined by the recurrence $F(n) = F(n-1) + F(n-2)$ for $n > 1$, $F(0) = 0$, $F(1) = 1$. The explicit formula (Levitin, §2.5, Appendix B):

$$F(n) = \frac{1}{\sqrt5}\left(\varphi^n - \hat\varphi^n\right), \qquad \varphi = \frac{1+\sqrt5}{2} \approx 1.61803, \quad \hat\varphi = -\frac1\varphi \approx -0.61803.$$

Since $|\hat\varphi| < 1$, the term $\hat\varphi^n$ quickly vanishes, and $F(n) \in \Theta(\varphi^n)$ (golden ratio φ).

Naive recursion

ALGORITHM F(n)
//Computes the nth Fibonacci number recursively by using its definition
//Input: A nonnegative integer n
//Output: The nth Fibonacci number
if n ≤ 1 return n
else return F(n − 1) + F(n − 2)
1–3. Size, operation, cases
Size $n$; the basic operation is addition; no separate cases.
4. Recurrence
$A(n-1)$ and $A(n-2)$ additions for the two calls and one for their sum: $$A(n) = A(n-1) + A(n-2) + 1 \ \text{ for } n > 1, \qquad A(0) = 0,\ A(1) = 0.$$
5. Solution
The right-hand side is not zero (an inhomogeneous recurrence). Rewrite it as $$[A(n) + 1] - [A(n-1) + 1] - [A(n-2) + 1] = 0$$ and substitute $B(n) = A(n) + 1$: $B(n) = B(n-1) + B(n-2)$, $B(0) = B(1) = 1$. This is the Fibonacci sequence started with two ones, that is, shifted one step ahead: $B(n) = F(n+1)$. Hence $$A(n) = F(n+1) - 1 = \frac{1}{\sqrt5}\left(\varphi^{n+1} - \hat\varphi^{n+1}\right) - 1.$$
Class
$A(n) \in \Theta(\varphi^n)$, exponential. In terms of the number of bits $b$, it is doubly exponential: $\varphi^{\Theta(2^b)}$.

The reason for the inefficiency is visible in the call tree: the same values are computed again and again. These are repeated subproblems: $F(n-2)$ is computed both from $F(n)$ and inside $F(n-1)$, and everything further down repeats. The recurrence itself hints at this: two calls on sizes only slightly smaller than $n$.

Memoization: memory functions

Memoization eliminates the repetitions while keeping the recursion. Levitin calls this technique memory functions and discusses it in §8.2 (on the knapsack problem): the recursion proceeds top-down, but a table is checked before each computation, so every value is computed only once.

ALGORITHM MemoFib(n)
//Memory function; F[0..n] is initialized with −1 (“not yet computed”)
if F[n] < 0
    if n ≤ 1  F[n] ← n
    else  F[n] ← MemoFib(n − 1) + MemoFib(n − 2)
return F[n]

Each $F(k)$ with $2 \le k \le n$ is computed once and costs one addition: $A_{memo}(n) = n - 1$. There are $2n - 1$ calls (for $n \ge 2$): $n + 1$ first calls, one for each of $F(0), \dots, F(n)$, plus $n - 2$ lookups of already computed values. The price is a table of $n + 1$ cells and a stack of depth $n$.

Iteration

It is even simpler to compute the numbers in order, bottom-up:

ALGORITHM Fib(n)
//Computes the nth Fibonacci number iteratively
F[0] ← 0; F[1] ← 1
for i ← 2 to n do
    F[i] ← F[i − 1] + F[i − 2]
return F[n]

The algorithm makes $n - 1$ additions, $\Theta(n)$. The array is unnecessary: each step uses only the two preceding values, so two variables and $O(1)$ memory suffice:

ALGORITHM Fib2(n)
//Two variables instead of an array
if n = 0 return 0
a ← 0; b ← 1          //a = F(i − 1), b = F(i)
for i ← 2 to n do
    c ← a + b
    a ← b; b ← c
return b

Summary: the same recurrence for the values can lead to an exponential ($\Theta(\varphi^n)$) or a linear ($n - 1$ additions) algorithm. It all depends on whether subproblems are solved repeatedly.

Recursion versus iteration

Time is not the only cost of recursion. Every unfinished call keeps a frame on the call stack: parameters, local variables, and the return address. Therefore, the extra memory of a recursive algorithm is proportional to the maximum depth of the recursion.

AlgorithmMaximum stack depthIterative version
Factorial $F(n)$$n + 1$$O(1)$
Tower of Hanoi$n$exists, without recursion
BinRec$(n)$$\lfloor\log_2 n\rfloor + 1$Binary, $O(1)$
Naive Fibonacci$n$ (with $2^{\Theta(n)}$ calls)Fib2, $O(1)$
Array sum Sum (below)$n + 1$$O(1)$
Maximum by halving MaxDC$\lceil\log_2 n\rceil + 1$MaxElement, $O(1)$

The depth is the length of the longest branch of the call tree, not the number of nodes. Hanoi makes $2^n - 1$ calls, but no more than $n$ of them are on the stack at the same time.

Own example 1. Recursive array sum

ALGORITHM Sum(A[0..n − 1])
//Sum of the array elements
if n = 0 return 0
else return Sum(A[0..n − 2]) + A[n − 1]
1–3. Size, operation, cases
Size $n$; the basic operation is addition; no separate cases.
4. Recurrence
$S(n) = S(n-1) + 1$ for $n > 0$, $S(0) = 0$ (an empty array needs no additions).
5. Solution
As for the factorial: $S(n) = n$.
Class
Time $\Theta(n)$, stack memory $\Theta(n)$: depth $n + 1$.

A loop makes the same $n$ additions with $O(1)$ memory. Can we keep the recursive form and not pay for the stack? This is the question of tail recursion.

Tail recursion

A call is a tail call if it is the last action of the function: its result is returned immediately, with no further computation (tail recursion). In Sum, an addition is still performed after the call, so the call is not a tail call. Let us move the accumulation into an accumulator parameter:

ALGORITHM SumAcc(A[0..n − 1], i, acc)
//Call: SumAcc(A, 0, 0)
if i = n return acc
else return SumAcc(A, i + 1, acc + A[i])

Now the call is a tail call: the current stack frame is no longer needed and can be reused, that is, the recursion can be turned into a loop. This is tail-recursion elimination. Levitin does not cover this topic; it is discussed in CLRS (Cormen et al., the Chapter 7 problems on the stack depth of quicksort): the tail call is replaced by assigning the parameters and jumping to the beginning of the procedure. For SumAcc, the extra memory then drops from $\Theta(n)$ to $\Theta(1)$. The number of additions does not change: $n$.

Python does not optimize tail recursion. Every call, tail or not, occupies a stack frame, and the depth is limited (by default sys.getrecursionlimit() returns 1000). Therefore, sum_acc on an array of 5000 elements fails with RecursionError, while an ordinary loop easily handles $10^6$ elements:

import sys

def sum_acc(a, i=0, acc=0):
    if i == len(a):
        return acc
    return sum_acc(a, i + 1, acc + a[i])   # tail call, but the stack still grows

print(sys.getrecursionlimit())             # 1000
try:
    sum_acc(list(range(5000)))
except RecursionError:
    print("RecursionError: depth exceeds the limit")

def sum_loop(a):                            # the same after tail-recursion elimination
    acc = 0
    for x in a:
        acc += x
    return acc

print(sum_loop(list(range(10**6))))

Practical takeaway: in Python, deep linear recursion is rewritten as a loop by hand.

Own example 2. Maximum by halving

Let us find the maximum of an array recursively: split the array into two halves, find the maximum of each, and compare them.

ALGORITHM MaxDC(A[l..r])
//Largest element of A[l..r]; call MaxDC(A[0..n − 1])
if l = r return A[l]
m ← ⌊(l + r)/2⌋
a ← MaxDC(A[l..m])
b ← MaxDC(A[m + 1..r])
if a > b return a
else return b
1. Input size
The number of elements $n = r - l + 1$.
2. Basic operation
The comparison $a > b$.
3. Cases
None: the comparison is performed in every call with $n > 1$ regardless of the values.
4. Recurrence
The left half contains $\lceil n/2\rceil$ elements, the right half $\lfloor n/2\rfloor$: $$C(n) = C(\lceil n/2\rceil) + C(\lfloor n/2\rfloor) + 1 \ \text{ for } n > 1, \qquad C(1) = 0.$$
5. Solution
For $n = 2^k$ both halves are equal: $C(2^k) = 2C(2^{k-1}) + 1$. The substitutions are as for Hanoi: $$C(2^k) = 2^2C(2^{k-2}) + 2 + 1 = \dots = 2^iC(2^{k-i}) + 2^i - 1 \overset{i=k}{=} 2^k\cdot0 + 2^k - 1 = n - 1.$$ The formula $C(n) = n - 1$ also holds for arbitrary $n$; this is proved by induction (problem C1).
Class
$C(n) = n - 1 \in \Theta(n)$.

Conclusion: there are as many comparisons as in MaxElement, since each comparison eliminates exactly one candidate. But recursion “by halves” gives a stack depth of only $\lceil\log_2 n\rceil + 1$, not $n$ as in the “linear” recursion of Sum. The shape of the call tree determines the memory, not just the time.

Own example 3. Fast exponentiation

Levitin discusses the nonrecursive version of this algorithm in §6.5; here we give the recursive version and its analysis via a recurrence relation.

Let us compute $a^n$ ($n \ge 1$) using $a^n = (a^{\lfloor n/2\rfloor})^2$ for even $n$ and $a^n = (a^{\lfloor n/2\rfloor})^2\cdot a$ for odd $n$.

ALGORITHM Power(a, n)
//Input: A number a and an integer n ≥ 1
//Output: a^n
if n = 1 return a
h ← Power(a, ⌊n/2⌋)
if n mod 2 = 0 return h ∗ h
else return h ∗ h ∗ a
1. Input size
The number of bits of the exponent $b = \lfloor\log_2 n\rfloor + 1$ (this is how Levitin measures the size for exponentiation, §6.5). For brevity, the formulas below are also written in terms of $n$.
2. Basic operation
Multiplication. The number of multiplications is $M(n)$.
3. Cases
They differ: an even exponent costs 1 multiplication, an odd one costs 2. Among all $n$ with the same number of bits $b$, the number of multiplications depends on how many ones the binary representation of $n$ contains.
4. Recurrence
$M(n) = M(\lfloor n/2\rfloor) + 1 + (n \bmod 2)$ for $n > 1$, $M(1) = 0$.
5. Solution
The best case for a given $b$ is a single one in the representation, $n = 2^{b-1}$: all intermediate exponents are even, and $$M(2^k) = M(2^{k-1}) + 1 = \dots = M(1) + k = k, \quad\text{that is, } M = b - 1.$$ The worst case for a given $b$ is all ones, $n = 2^b - 1 = 11\ldots1_2$: every level except the last costs 2 multiplications, $M = 2(b-1)$. Both inputs have the same size $b$. In general, $\lfloor\log_2 n\rfloor \le M(n) \le 2\lfloor\log_2 n\rfloor$ (proof in problem C2).
Class
$M(n) \in \Theta(\log n)$, versus $n - 1$ multiplications for the brute-force algorithm. For example, $a^{1000}$: 14 multiplications instead of 999.

The exact formula, verified by a program for all $n \le 2000$: $M(n) = \lfloor\log_2 n\rfloor + \nu(n) - 1$, where $\nu(n)$ is the number of ones in the binary representation of $n$. For $n = 1000 = 1111101000_2$: $9 + 6 - 1 = 14$.

Empirical verification

The experiment plan is the same as in Module 1. For a recursive function, it is convenient to keep the counter in a global variable or to pass it as a list. It is incremented where the basic operation is executed, not on entry to the function, unless calls are what is being counted.

moves = 0

def hanoi(n, src, dst, aux):
    global moves
    if n == 1:
        moves += 1                     # move one disk
        return
    hanoi(n - 1, src, aux, dst)
    moves += 1
    hanoi(n - 1, aux, dst, src)

for n in range(1, 21):
    moves = 0
    hanoi(n, "A", "C", "B")
    print(n, moves, 2**n - 1, moves == 2**n - 1)

Conclusions. For the factorial ($n$ multiplications, depth $n + 1$), Hanoi ($2^n - 1$ moves and calls), BinRec ($\lfloor\log_2 n\rfloor$), Fibonacci ($F(n+1) - 1$ and $n - 1$), MaxDC ($n - 1$ comparisons), Power ($\lfloor\log_2 n\rfloor + \nu(n) - 1$), and Sum ($n$), the counter matched the formula for all tested $n$. The experiment with sum_acc confirmed that Python does not eliminate tail recursion: at $n = 5000$ a RecursionError occurs.

Summary

  • The plan for analyzing a recursive algorithm differs in steps 4 and 5: instead of a sum, a recurrence relation is set up and solved, and the initial condition is taken from the line where the recursion stops.
  • The method of backward substitutions: substitute three times, see the pattern after $i$ steps, and choose $i$ that reaches the initial condition. The result is verified by induction.
  • Factorial: $M(n) = n$. The recurrence for the values and the recurrence for the number of operations are different things.
  • Tower of Hanoi: $M(n) = 2^n - 1$; by the call tree, $\sum_{l=0}^{n-1}2^l = 2^n - 1$. The succinctness of recursion may mask its inefficiency.
  • BinRec: solve for $n = 2^k$ and extend to all $n$ by the smoothness rule; exactly $\lfloor\log_2 n\rfloor$.
  • Naive Fibonacci is $\Theta(\varphi^n)$ because of repeated subproblems. Memoization (memory functions, §8.2) and iteration give $n - 1$ additions; iteration needs only two variables.
  • The memory of a recursion is the depth of the stack. Tail recursion can be replaced by a loop, but Python does not do this.

Formula cheat sheet

factorial
$M(n) = M(n-1) + 1,\ M(0) = 0 \Rightarrow M(n) = n$
Tower of Hanoi
$M(n) = 2M(n-1) + 1,\ M(1) = 1 \Rightarrow 2^n - 1$
Hanoi call tree
$C(n) = \sum_{l=0}^{n-1} 2^l = 2^n - 1$
BinRec
$A(n) = A(\lfloor n/2\rfloor) + 1,\ A(1) = 0 \Rightarrow \lfloor\log_2 n\rfloor$
naive Fibonacci
$A(n) = A(n-1) + A(n-2) + 1 \Rightarrow F(n+1) - 1 \in \Theta(\varphi^n)$
Fibonacci, memoized / iterative
$n - 1$ additions
$x(n) = x(n-1) + c$
$x(n) = x(0) + cn$
$x(n) = x(n-1) + n$
$x(n) = x(0) + \frac{n(n+1)}{2}$
$x(n) = 2x(n-1) + 1$
$x(n) = 2^n x(0) + 2^n - 1$
$x(n) = x(n/2) + 1$, $n = 2^k$
$x(n) = x(1) + \log_2 n$
$\varphi$
$\varphi = \frac{1+\sqrt5}{2} \approx 1.618$,   $F(n) \in \Theta(\varphi^n)$
smoothness rule
$T$ eventually nondecreasing, $f$ smooth, $T(n) \in \Theta(f(n))$ for $n = b^k$ ($b \ge 2$) $\Rightarrow$ for all $n$
